# 有界 PD 停止原因诊断（冻结前设计）

固定 Newton 1.7.0 / `7e75abe28b8d69522bc0b34837aaed2c303dff5a`，CPU、单 world。旧数据及源码只读。

## 现有证据

`legacy-readonly-check.json` 独立读取旧两次正式 PD 运行。各 80 个已求解样本均为 200 次迭代、converged=0；r_p 在 9.93e-9 至 1.12e-8，r_d 不超过 2.61e-15，只有 r_c 在 4.02e-7 至 4.57e-7 J 超过冻结的 1e-7。独立应用三个停止条件与已存 status 完全一致，初始未定义 status 未参与统计。这排除旧分析的分母/初始占位错误，但旧 NPZ 没有内迭代变量，不能据此确认停滞或精度下限。

有界行的互补残差为 `abs((x-lower)*max(z,0)+(upper-x)*max(-z,0))`。它使用未投影 x，而不是已经截断到力限的 y。变量及界限经过预条件缩放，乘积单位仍是 J。假说是很小的 x 与边界差值乘上较大的驱动对偶速度，留下不满足严格门槛的互补残差。该假说必须通过保存 x/y/z/P/bounds 后验证。

## 可区分的五个设置

场景沿用旧单转子：质量1 kg，COM偏移0.5 m，COM惯量1 kg m²，铰轴有效惯量1.25 kg m²；无重力/碰撞，ke=100、kd=2、力限±1 Nm，目标前40步+1 rad、后40步−1 rad。dt=0.005 s，总时长0.4 s。

1. baseline：原200次、三容差1e-7、加速开启、默认对角预条件、containers暖启动。
2. budget1000：仅最大迭代200→1000，判断原预算不足还是持续停滞。
3. compl1e6：仅互补容差1e-7→1e-6，测试具体停止门槛；始终另外计算原严格门槛，不能称为根因已修复。
4. noaccel：仅关闭加速，隔离加速/重启路径。
5. noprecondition：仅关闭动力学预条件，隔离缩放影响。

每设置2个独立进程，共10个正式run；baseline可复用于4个配对案例，不重复计数。未做任意多参数搜索。所有物理验收门槛沿用旧实验，收敛成功不是预设必需结果。

## 观测与独立验收

公共 API 建模/创建solver/step；只读包装内部原 `_step` 或 `_step_accel`，每次精确委托原方法一次，前后读取内变量，不写入算法数据。每个有效内迭代保存 x/y/z、上一轮 x、参与该轮的 y/z（加速分支为 y_hat/z_hat）、P、界限、rho/eta、完整status。状态停止后的固定CPU空转调用不再重复记为迭代。

每个物理时间步保存 body/joint q/qd、力矩/控制、终止残差/步数/布尔状态；初始status由defined mask区分，原始物理数组全部有限。统一时间字段保存 `t` 和兼容 `time`。lambda初始延迟分配由内部已分配数组补齐，schema变更必须失败，不得静默丢列。

独立 NumPy 分析重算 r_p、r_d、r_c（float64与float32两种算术）以及配置停止条件和原1e-7严格条件；误差允许量按表达式舍入误差量级预先定义。所有内迭代数必须对应终态迭代数。baseline还必须匹配旧物理轨迹及旧200次/未收敛状态，以验证观测包装未改变结果。安装的受锁Python全树逐文件核验，不能只核验wrapper路径。

长期预算仍未改善只能支持“不是简单增加到1000次就能解决”。同时报告尾20迭代的精确不变/短周期、x距界限的ULP、对偶更新相对z的ULP和乘积残差，才讨论与float32量化一致的证据；没有匹配的高精度实现，不声称证明普适精度下限。原始失败、未改善和harness错误全部保留。

## 冻结与输出

`protocol-draft.json` 是待审协议，禁止凭草稿运行。root写入冻结状态/时间并确认SHA后，runner要求显式传该SHA。每run归档协议/runner/environment/source验证/config/NPZ/日志；独立分析输出analysis与4个可聚合配对publication案例。这里的每迭代同步观测改变运行开销，因此不做性能排名。
